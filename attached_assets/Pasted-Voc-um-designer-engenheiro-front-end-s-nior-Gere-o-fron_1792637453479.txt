Você é um designer-engenheiro front-end sênior. Gere o front-end completo do **AdaptAI** em React + TypeScript + Vite + Tailwind CSS (componentes no estilo shadcn/ui, ícones lucide-react, roteamento com react-router). Idioma da interface: pt-BR, com acentos corretos. Não gere backend.

## 1. Produto
AdaptAI é um sistema de adaptação de conteúdo educacional (Hackathon ONE G10). O usuário envia documentação técnica densa (PDF, Markdown ou texto) e recebe um pacote de estudo personalizado: Tutorial, Flashcards, Quiz, Resumo ou Roteiro de Aula. A adaptação depende do perfil do destinatário, do nicho e do nível de detalhe. Todo conteúdo é ancorado na fonte original (RAG), com score de fidelidade visível. O aluno ganha XP, evolui por 5 níveis e faz Teste de Nível. O sistema sugere e alerta, nunca bloqueia.
Diferenciais que a interface precisa mostrar: Trilha de Evolução gamificada, Adaptação Universal (rótulos por domínio), Motor de Analogias, ancoragem na fonte.

## 5. Camada de dados (obrigatório)

O app deve funcionar 100% com dados mockados, SEM nenhuma requisição de rede ativa. Porém, o código real de integração com a API deve estar completo, tipado e COMENTADO dentro de cada função de serviço, pronto para eu descomentar e apagar o mock.

### Estrutura
- `src/services/http.ts`: cliente base com fetch. Todo o conteúdo fica comentado, exceto os tipos exportados. Deve conter, comentados: `API_BASE_URL = "/api/v1"`, helper `request<T>(path, options)` que injeta `Authorization: Bearer <token>`, faz parse de JSON, e lança `ApiError` quando a resposta vier no formato `{status:"erro", codigo, mensagem, detalhes[], request_id}`. Tratamento de 401 NAO_AUTENTICADO: limpar token e redirecionar para /login. Upload usa `FormData` (multipart), sem definir Content-Type manualmente.
- `src/services/auth.service.ts`, `usuarios.service.ts`, `documentos.service.ts`, `adaptacoes.service.ts`, `perfil.service.ts`, `health.service.ts`: um arquivo por recurso, uma função por endpoint do contrato.
- `src/mocks/`: fixtures e `delay(ms)` (400–1200 ms) para simular latência.

### Padrão obrigatório em CADA função de serviço
Cada função tem dois blocos claramente delimitados:

export async function login(body: LoginRequest): Promise<LoginResponse> {
  // ===== REAL API — descomente para integrar (e remova o bloco MOCK) =====
  // return request<LoginResponse>("/auth/login", {
  //   method: "POST",
  //   body: JSON.stringify(body),
  // });
  // ========================================================================

  // ===== MOCK — remover após integrar =====
  await delay();
  return mockLoginResponse;
  // =========================================
}

### Regras
- Cada função mapeia 1:1 com o contrato: POST /auth/cadastro, POST /auth/login, GET /usuarios/me, GET /health, POST /documentos (multipart), POST /adaptacoes, GET /adaptacoes, GET /perfil.
- O bloco real usa os tipos TypeScript do contrato, com o método HTTP, a rota, o body e a autenticação corretos. Rotas públicas (/auth/cadastro, /auth/login, /health) NÃO enviam Authorization.
- Em `http.ts`, comente também o tratamento dos códigos: 401, 409 EMAIL_JA_CADASTRADO, 422 VALIDACAO_FALHOU (com `detalhes` mapeados para erros de campo do formulário) e 501 NAO_IMPLEMENTADO (mensagem "Em breve").
- As telas e hooks consomem APENAS as funções de serviço. Nenhum componente chama fetch nem importa fixtures diretamente. Assim, integrar = descomentar nos serviços.
- Os mocks também simulam os erros do contrato por gatilhos óbvios (ex.: e-mail "duplicado@teste.com" → 409; senha "errada" → 401; documento com título "erro" → 422) para eu testar os estados de erro na UI.
- Token: helper `tokenStorage` (get/set/clear, memória + localStorage) já ativo, pois não depende da API. Rotas protegidas funcionam com o token mock.
- Crie `src/services/README.md` com uma tabela: função → endpoint → arquivo, e o passo a passo de integração: (1) descomentar `http.ts`, (2) descomentar o bloco REAL em cada serviço, (3) apagar o bloco MOCK, (4) conferir `API_BASE_URL` e o proxy do Vite (`/api` → `http://localhost`) para dev.
- Configure o proxy no `vite.config.ts` já pronto para dev: `/api` e `/docs` apontando para o Nginx/backend, deixando o bloco comentado se necessário.
